# 解题笔记

## 核心思路

一边遍历数组，一边记录已经见过的数字及其下标；对当前数字 `nums[i]`，查找此前是否出现过 `target - nums[i]`。

## 从暴力到最优

### 暴力枚举

用两层循环枚举所有不同下标 `i`、`j`，检查 `nums[i] + nums[j] == target`。为了不重复、不使用同一元素两次，让 `j` 从 `i + 1` 开始。

这种方法一定能找到答案，但最多需要检查约 `n² / 2` 对数字。

### 优化观察

固定当前数字 `nums[i]` 后，另一个数字必须等于：

```text
needed = target - nums[i]
```

因此，问题变成：怎样快速判断 `needed` 是否在此前的数字中出现过？使用映射保存“数字 → 下标”，即可快速查找。

先查找、再保存当前数字，可以保证找到的是此前的另一个位置，不会重复使用当前元素。

## 算法步骤

1. 创建映射 `valueToIndex`，保存已经遍历过的数字和下标。
2. 从左到右遍历数组，当前位置为 `i`。
3. 计算 `needed = target - nums[i]`。
4. 如果映射中存在 `needed`，返回其下标和 `i`。
5. 否则，把 `nums[i]` 和 `i` 放入映射，继续遍历。

## 正确性

当算法在位置 `i` 找到 `needed` 时，映射中的下标来自此前的位置 `j`，所以 `j != i`。根据 `needed = target - nums[i]`，可得 `nums[j] + nums[i] = target`，返回的两个下标有效。

题目保证存在唯一答案。设答案下标为 `j < i`：遍历到 `j` 后，算法会记录 `nums[j]`；遍历到 `i` 时，计算出的 `needed` 正好是 `nums[j]`，因此一定能找到并返回答案。

## 复杂度

- 暴力枚举：时间 `O(n²)`，额外空间 `O(1)`。
- 映射方法：平均时间 `O(n)`，额外空间 `O(n)`。

## 手推示例

输入：`nums = [2, 7, 11, 15]`，`target = 9`。

| `i` | `nums[i]` | `needed` | 查找前的映射 | 结果 |
|---:|---:|---:|---|---|
| 0 | 2 | 7 | `{}` | 没找到，记录 `2 → 0` |
| 1 | 7 | 2 | `{2 → 0}` | 找到下标 0，返回 `[0, 1]` |

## 易错点

- 返回的是下标，不是两个数字。
- 不能返回同一个下标两次。例如 `[3, 2, 4]`、目标值 `6` 不能返回 `[0, 0]`。
- 必须先查找再插入当前数字，否则可能把当前元素匹配给自己。
- 重复数字是允许的。例如 `[3, 3]`、目标值 `6` 的答案是 `[0, 1]`。
- `unordered_map` 的 `find` 返回迭代器；用 `it != valueToIndex.end()` 判断是否找到。
